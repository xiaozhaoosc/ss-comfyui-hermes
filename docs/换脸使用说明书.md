# 换脸使用说明书

> 本机：RTX 4060 Ti 16G / ComfyUI 8188 / onnxruntime-gpu 1.24.4（CUDA EP 已确认实际绑定）
> 换脸算子是 **onnxruntime**（inswapper_128 + RetinaFace），不走 torch

## 0. 三种用法怎么选

| 想要 | 用哪个 | 输出 |
|---|---|---|
| 一张图换脸、试参考脸效果 | `workflows/v1/faceswap_video_ui.json` 去掉两个 VHS 节点 | 单张图 |
| 单条视频 | 同上的 UI 工作流（GUI 里点运行） | 1 条 mp4 |
| 成批视频 + 水印 + 语录 | `tools/batch_faceswap_overlay.py` | 每条一个语录命名的 mp4 |
| 成批视频 + 水印 + 保留原BGM | `tools/batch_faceswap_watermark.py` | 每条原名 mp4 |
| 不经 ComfyUI，venv 本地直跑 | `tools/batch_faceswap_gpu.py`（备用，本机未复验） | 每条一个 mp4 |

## 2. 路径 A/B：UI 工作流

### 2.1 `workflows/v1/faceswap_video_ui.json`（单参考脸，与批量脚本同参）

打开 ComfyUI → 拖入该 json，四个节点串好的：

```
VHS_LoadVideo ─┬─ IMAGE ─────────→ ReActorFaceSwap ─ SWAPPED ─→ VHS_VideoCombine
               └─ audio ────────────────────────────────────────→ (audio)
LoadImage(参考脸) ─ IMAGE ─→ source_image
```

操作三步：

1. **节点 1 选视频**。`custom_width/custom_height` 保持 **0**（=保留源分辨率；填非 0 会强制缩放）
2. **节点 2 选参考脸**
3. **节点 4 把 `frame_rate` 改成源视频帧率**

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate -of csv=p=0 "视频.mp4"
# 输出 30/1 → 填 30
```

> ⚠️ 填错不会报错，只会**倍速/慢放**（帧数不变，播放时长变）。这是本机踩过两次的坑。

参数默认值与生产一致：`inswapper_128.onnx` + `retinaface_resnet50` + `face_restore_model=none`。

**换多张脸**：`input_faces_index` 按人脸面积从大到小排序，字符串逗号分隔 —— `"0"` 只换最大那张，`"0,1"` 换前两张。
排查顺序把 `console_log_level` 改 2，看控制台。

**单张图换脸**：把两个 VHS 节点删掉（或 mute），`ReActorFaceSwap` 的 `input_image` 改接一个 `LoadImage`，
再接 `SaveImage` 即可 —— 换脸节点本身与图片/视频无关。

### 2.2 `workflows/v1/faceswap_video_multiref_ui.json`（2~3 张参考脸融合）

```
LoadImage×3 → ImageBatch×2 → ReActorBuildFaceModel(Mean) → face_model → ReActorFaceSwap
```
`ReActorFaceSwap` 的 `source_image` 留空（走 `face_model` 输入）。

默认三个槽位都填同一张图，只是保证开箱能跑；实际用时换成**同一个人的 正脸 / 左侧 15-30° / 右侧 15-30°**。

## 3. 参考脸怎么准备（要不要加侧脸）

**结论：加侧脸不会直接提高精确度，但"多张正脸做融合"能稳住身份。**

代码依据：

- `reactor_core/inswap.py` 的 `INSwapper.get()` 只用源脸的 **512 维身份向量**（`normed_embedding`）+ **目标脸**的 5 点做对齐 → 源侧**不携带姿态信息**
- `nodes.py: BuildFaceModel.blend_faces()` 把多张参考脸的 embedding 做 `Mean / Median / Mode` 融合，`bbox / kps / pose` 直接沿用第一张

所以：

| 做法 | 有没有用 | 说明 |
|---|---|---|
| 2~4 张同一人、角度差 <30°、光照不同的正脸/微侧脸，Mean 融合 | ✅ 有用 | 降噪、抗模糊/逆光/轻微遮挡，身份更稳 |
| 塞 60~90° 大幅侧脸 | ❌ 有害 | 把 embedding 拉向"平均脸"，与真实身份相似度反而下降 |
| 想靠侧脸参考"让侧脸帧也换得上" | ❌ 无效 | 目标帧检测不到脸才是不换的原因，属于 retinaface 在**目标侧**的极限 |
| 目标视频侧脸多 | 调目标侧 | 已经很稳：`retinaface_resnet50` 是最高档；更极端可试 `YOLOv5l` 或调 `input_faces_index` |
| 想要更清晰（不是更像） | 换 restore | `face_restore_model` 改 `GFPGANv1.4.pth` / `codeformer.pth`，`face_restore_visibility` 建议 0.5（1.0 塑料感） |

**量化验证融合有没有白做**：加一个 `ReActorFaceSimilarity`，`image1`=主参考face、`image2`=换脸后抽帧，
看余弦相似度。融合前后对比，不掉就是有效。

**参考图硬要求**：正脸、清晰、无遮挡、无重影；同一个人；分辨率 ≥512px；单张图里只放一张该人的脸（
`source_faces_index` 默认取最大那张）。

## 4. 路径 C：批量换脸（当前主力）

### 4.1 两个批量脚本的区别

| 脚本 | 水印 | 语录 | 音频 | 命名 | 适用 |
|---|---|---|---|---|---|
| `batch_faceswap_overlay.py` | ✅ | ✅ | 原声 0.10 + BGM 0.75 | 语录命名 | 竖屏短剧/自媒体成片 |
| `batch_faceswap_watermark.py` | ✅ | ❌ | 保留原 BGM（可叠 BGM） | 沿用源文件名 | 只加水印、保留原声场 |

两者共用：提交换脸到 ComfyUI（按源帧率自动设 `frame_rate`）、跳过已有产物、`_submit_manifest.jsonl` 记录、`--submit-only / --poll-only` 断点续跑。

### 4.2 常用命令（**路径一律绝对**）

```bash
# 全量跑（换脸 + 水印 + 语录）
"C:/Users/kenzhao/anaconda3/python.exe" tools/batch_faceswap_overlay.py \
  --input  "D:/ai_projects/ComfyUI/input/hitomi_insta_batch/ayano (insta_ayano.fj)" \
  --output "D:/ai_projects/ComfyUI/output/2026-10-12/hitomi_batch/ayano (insta_ayano.fj)" \
  --face   "D:/ai_projects/ComfyUI/input/ken4/face/gpt/duo.png" \
  --original-dir "D:/ai_projects/ComfyUI/input/hitomi_insta_batch/ayano (insta_ayano.fj)"

# 只跑换脸，不后处理（产物留原名，便于抽帧对画质）
... --limit 2 --submit-only

# 已经有换脸结果，只补后处理
... --skip-faceswap \
  --input  ".../ayano (insta_ayano.fj)" \
  --output ".../ayano (insta_ayano.fj)_final" \
  --original-dir "D:/ai_projects/ComfyUI/input/hitomi_insta_batch/ayano (insta_ayano.fj)"

# 先试参数不提交
... --dry-run
```

### 4.3 断点续跑与幂等

- **换脸**：`faceswap_done()` 看批次目录里有没有该源的产物 → 有就跳过。**重跑同一条命令即可补齐缺的**，不会重复换脸
- **后处理**：`_done_map.json` 记录已处理过的 stem → 自动跳过
- **提交记录**：`<批次目录上级>/_submit_manifest.jsonl`，每行带 `prompt_id`，可事后查 `/history`
- **队列被别的会话清空**（本机多 agent 常见）：重跑 4.2 第一条命令即可，只会补缺

### 4.4 venv 本地直跑（备用）

`tools/batch_faceswap_gpu.py` 不经 ComfyUI，直接 insightface + inswapper + GFPGAN：

```bash
cd /d/ai_projects/ComfyUI && PATH="/c/Users/kenzhao/cudnn9/bin:$PATH" \
  venv/Scripts/python.exe tools/batch_faceswap_gpu.py \
  --video-dir "输入目录" --face-dir "人脸目录" --output-dir "输出目录"
```

它的 `check_gpu()` 会建真会话验证 `get_providers()`，回落 CPU 直接退出（已修）。
**注意：本机今天没有用它实跑过整批**，主力仍是 ComfyUI 路径。

## 5. 耗时与规划（实测）

| 分辨率 | 单帧 | 10 秒 / 30fps（300 帧） | 20 秒（600 帧） |
|---|---|---|---|
| 720×1280 | **0.55 秒** | ≈2.9 分钟 | ≈5.6 分钟 |
| 1080×1920 | **1.11 秒** | ≈5.8 分钟 | ≈11.2 分钟 |

- 另有 **约 10 秒固定开销**（模型冷启动，第一次跑才明显）
- 1080p 单帧成本约为 720p 的 2 倍：换脸算子固定 128×128，多出来的是解码/编码与整帧搬运
- 加 `face_restore`（GFPGAN/CodeFormer）会额外增加耗时，未单独实测
- 实际批量完成时间还要加**排队/插队**：同机其它会话的 H3 任务每次 15~21 分钟

换算口诀：**预算 ≈ 帧数 × 0.55（720p）或 × 1.11（1080p）**

## 6. 常见问题排查

| 现象 | 根因 | 处理 |
|---|---|---|
| 产物倍速/慢放 | `VHS_VideoCombine.frame_rate` 与源不一致 | 按源 fps 填；批量脚本已自动 `probe_fps` |
| 越来越慢（3 秒/帧） | CUDA EP 没绑上，回落 CPU | 看日志 `actual=`；启动命令前置 `cudnn9\bin` |
| 报 `cudnn64_9.dll missing` | PATH 没有 cuDNN9 | 同上 |
| 换脸没变化 | 目标帧没检出脸 / `input_faces_index` 选错 | `console_log_level=2` 看检测顺序；参考脸换正脸 |
| 同一条被跑两遍 | 批次目录被改名或产物被删 | 正常会 `faceswap_done` 跳过；确认目录一致 |
| 后处理少了几条 | 随机语录重名覆盖（已修，但仍可能撞历史文件） | 现在 `used_names` 预置已有文件名，不会覆盖 |
| `Database is locked` | 起了两个 ComfyUI | 先全杀 `main.py` 再启，只留 1 个 |
| 脚本报 `relative_to` ValueError | 参数传了相对路径 | **所有路径参数改绝对路径** |
| 队列突然空了 | 其他会话清了队列 | 重跑提交命令，已产出的会自动跳过 |
