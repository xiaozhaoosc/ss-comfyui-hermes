# AI 漫剧智能体团队 2.0 — 工作流速查表

> 基于公众号文章《用 WorkBuddy + HY3 搭建了一个AI漫剧智能体团队2.0！0 积分跑完全套资产设计！》整理。
> 用途：一页式操作手册，照着执行即可从小说跑通到分镜投产包。

---

## 1. 项目概览

| 项 | 内容 |
|---|---|
| 团队规模 | 6 个执行角色 + 1 个总调度 |
| 输入 | 1 篇约 3700 字短篇小说（docx） |
| 输出 | 大纲 → 角色设定 → 美术资产 → 剧本 → 分镜投产包（全链路） |
| 主力模型 | 混元 **HY3**（免费，跑技能与设定集） |
| 付费项 | 团队头像生成 + 1 条测试视频 |
| 技能来源 | `github.com/eternityspring/shuohao-skills`（作者烁皓，Apache-2.0，4300+ Star） |
| 运行环境 | Node 18+，**零 npm 依赖** |
| 装配方式 | 将仓库 `skills/` 目录整体复制进专家包 |

**核心价值**：把原本需要美术、编剧、分镜师协同数天的资产筹备，压缩为「一次上传 + 等待」，且每一步都留有可审计、可回滚、可二次出图的标准化锚点。

---

## 2. 六道流水线技能（安装顺序 = 工序顺序）

| 顺序 | 技能名 | 职责 | 质量门 / 关键产出 |
|---|---|---|---|
| 1 | `novel-outline` | 小说 → 短剧大纲五件套 | **14 道**质量门 |
| 2 | `novel-characters` | 角色设定集 | 形象提示词 + 音色提示词 |
| 3 | `novel-art` | 场景 & 道具美术设定集 | **10 道**质量门 |
| 4 | `novel-script` | 剧本（场次 + 节拍流） | 自动折算时长，**10 道**门 |
| 5 | `novel-storyboard` | 分镜（段落 → 分镜 → 分镜图） | 直出 H3 / Seedance 投产包，**18 道**门 |
| 6 | `character-refs` | 唯一真出图能力 | 支持 Qwen / Codex / GPT Image |

> 第一代团队由 DeepSeek Pro V4 手写，交接细节缺失；烁皓这套技能补齐了各环节的标准化约束。

---

## 3. 七角色与协作架构

| 角色 | 职能 | 绑定技能 |
|---|---|---|
| **钟秉钧** | 短剧总调度：拉人、排序、质量门终审，**不写一字** | 流水线总控 |
| **章立纲** | 剧情架构师（首节点，产出大纲） | `novel-outline` |
| **郝传神** | 人物设定师（角色卡、形象音色锚点） | `novel-characters` |
| **陆定景** | 美术设定师（场景/道具视觉规范） | `novel-art` |
| **言成章** | 编剧（三集剧本、台词节拍） | `novel-script` |
| **乔定帧** | 分镜导演（分镜切分 + 视频模型提示词） | `novel-storyboard` |
| **闵定妆** | 角色定妆师（支线单独调用，不占主线） | `character-refs` |

**协作规则**

- 所有信息必须经过**总控中转**，执行节点之间**无直连通道**。
- 上游产物若被下游私下修改极易失真，统一过总控 = 每条信息多一次核对。
- 团队组建完成后收纳于「我的专家团」，随时召唤复用。
- 命名基调：**「贝阵」**；可提前传图省头像积分（默认生成全部 8 张团队头像）。

## 4. 实操命令流程

```
① 召唤团队  →  ② 挂载专家团  →  ③ 模型选 HY3  →  ④ 上传 docx  →  ⑤ 发送指令
```

**指令原文（可直接复制）**

```
把这本短篇小说改编成 3 集竖屏漫剧，从大纲一路做到分镜
```

**执行链（串行）**

```
章立纲(大纲) → 郝传神(人物) → 陆定景(美术) → 言成章(剧本) → 乔定帧(分镜)
```

- 每过一关，总调度自动重跑对应质量门。
- 未通过即**打回重修**，不允许带已知问题流转。
- 全程几乎无需干预，仅观察进度条逐个点亮。

## 5. 产出的四类资产

| 资产类型 | 具体数据 |
|---|---|
| **分镜包** | 26 段 / 70 个切，总时长 **5′13″**，每段预填视频模型提示词 + 投产包 |
| **剧本** | 3 集 / 30 句台词，总时长 **5′21″** |
| **美术设定** | 4 个场景 + 3 件道具，全部标注一致性锚点 |
| **角色设定卡** | 苏晚、收银员双角色卡（形象提示词 + 音色参数） |

> 每张设定卡附带可直接复制的出图提示词与版面指令。作者将其喂给 GPT 批量生成角色三视图、场景图、道具图后回填设定集空位，彻底避免「回头猜当初怎么写的」问题。

## 6. 成本分析

### 6.1 单价表

| 项目 | 计费方式 | 积分消耗 |
|---|---|---|
| **HY3**（大纲 / 设定集 / 技能执行） | 免费 | **0** |
| 团队头像生成 | 8 张 | 少量（可提前传图省积分） |
| 混元 文生图 / 图生图 | 单张 | 5–10 / 张 |
| Seedance 即梦 2.5 视频 | 5 秒 | 50–100 / 5 秒 |
| WorkBuddy 内调用 Seedance | 文/图生视频 | 同上 |

### 6.2 实测

| 项 | 数值 |
|---|---|
| 首段分镜试跑 1 条视频 | 实扣 **≈200 积分** |
| 全流程积分消耗来源 | 仅「团队头像生成」+「单条测试视频」 |
| 技能执行 / 大纲 / 设定集 | 全部由免费 HY3 跑通，**0 积分** |

### 6.3 测试视频质量评估

- ✅ 动作逻辑正确
- ❌ 人脸与服装一致性仍有缺口
- 结论：**更适合流程验证，而非直接出片**；精修成片建议跳转即梦、LibTV 等专业场。

| 路线 | 方案 | 适合人群 | 注意事项 |

| **A** | ComfyUI + Wan2.2 本地批量出镜头 | 有 NVIDIA 显卡、想批量生产 | 吃显卡，推荐租云主机 |
| **B** | MiniMax-H3 本地部署 | 需要带音频输出的复杂分镜 | 2K 完整工作流暂未全离线 |

## 8. 核心结论

1. 闭源壁垒正在被 Agent 流水线消解，但「能复现功能」≠「能复现业务价值」。
2. 这套漫剧团队的价值在于：把数天的资产筹备压缩成一次上传 + 等待。
3. 每一步都留有可审计、可回滚、可二次出图的标准化锚点。
4. 对手里有小说 / IP、卡在视觉化第一步的创作者，是当前门槛最低的全链路验证方案。

**一句话**：赋能全在免费 HY3，积分只花在头像和测试视频上。
