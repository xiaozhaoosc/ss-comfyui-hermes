# MiniMax H3 视频 LoRA 训练落地文档（全链路方案）

> 目标：用自己的角色/风格素材，训练一个 H3 专用 LoRA，加载进 ComfyUI 并嵌入现有 workflow，
> 使 `h3_xinniang_v1` 这类视频在保持人设/风格一致的同时可复用。
> 本文档是**方案**：先评审可行性，再进入数据准备与训练。你提供训练素材后，我来执行各阶段。

***

## 0. 结论速览

- **硬件**：RTX 4060 Ti **16GB 显存**。能训，但 H3 是超大视频模型（语义 CLIP 32B + 视频 UNet），
  LoRA 训练需要 **offload / 梯度检查点 / 较小 batch**，16GB 属于"能跑但勉强"，建议用离线加载控制显存。

- **可行性风险**：H3 的第三方 LoRA 训练脚本目前**远不如 kohya 对 SD/SDXL/Flux/Wan 成熟**。
  需先确认本仓库/社区是否有可用 H3 训练入口，再动手。若没有成熟入口，见"4. 备选路线"。

- **时间**：由数据量×分辨率×epoch 决定，区间见"3. 时间评估"。

***

## 1. 硬件评估（RTX 4060 Ti 16GB）

| 项目      | 情况                                           | 结论                                               |
| ------- | -------------------------------------------- | ------------------------------------------------ |
| 显存      | 16GB                                         | 训 LoRA 可（需 offload/低 batch/梯度检查点）；跑当前 480p 生成也安全 |
| CUDA/驱动 | 610.88                                       | 满足 PyTorch + 视频模型                                |
| 训练峰值显存  | 单样本 LoRA 预估 6–11GB（含 CLIP 语义塔 offload 到 CPU） | 建议 `attention_rope_fp32` 类权重复核大小设置               |
| 速度基准    | 4060 Ti FP16 算力中等                            | 视频样本在线/离线训练有效吞吐约几十秒/条 → 见时间评估                    |

> 若训练明显吃紧：用**冻结视频 UNet、仅训 LoRA 分支（rank 16–32）**、梯度检查点、`cache_latents`。

## 2. 素材要求（你需提供）

**格式**：MP4/序列帧（建议 24fps，每段 ≥3s）。
**数量**：风格 LoRA **30–100 条**；单一人设角色 **200–500 条** 起步（条数越多一致性越好）。
**分辨率**：与生成目标一致更佳，建议 ≥ 544×960（9:16）或对应目标分辨率。
**标注**（Text Prompt）：

- 每条配一段英文描述（人物外貌、服装、动作、机位、时长）。

- 若训角色 LoRA，标注中固定角色触发词（如 `cn bride char`）；风格则写统一风格词。

- 提供 `data.jsonl` / 文件名映射 均可，我来统一成 MyCog/Paddle 式或脚本式列表。

> 素材最好**干净单主体**：背景少杂物、人脸清晰、光线稳定，否则 LoRA 学到杂质。

***

## 3. 训练链路（训练 → 加载 → 嵌入 workflow）

### 3.1 训练

1. 确认/搭建训练器（见下方"训练器选择"）。
2. 准备数据集（上节素材）+ 标签文本。
3. 训练脚本关键超参：

   - 分辨率：`544×960`（与现有生成一致）

   - 帧长：`16–24 帧/样本`（短于 124，专业视频 LoRA 常用短窗）

   - LoRA rank：`16–32`，`alpha = rank`，target 为 UNet attention 与 feedforward

   - 优化器：AdamW8bit / AdamW，`lr 1e-4`，cosine 调度

   - `batch 1` + 梯度累积；`gradient_checkpointing=True`；`offload` 语义塔
4. 产出：`h3_xxx.safetensors`（H3 LoRA 权重）+ 配对的 `trigger_word`。

> **训练器选择（需先行验证）**：H3 官方商用接入以 API 为主；本地训练脚本在社区逐步出现但**未稳定**。
> 我拿到你的素材后会先 `git`/HuggingFace 检索是否有适配本仓库 H3 构架(见下)的训练入口；
> 若无，走第 4 节的"备选路线"，不让你空等。

### 3.2 加载进 ComfyUI

- 将 `h3_xxx.safetensors` 放到：
  `D:\ai_projects\ComfyUI\models\loras\`

- 使用对应 LoRA 加载节点（H3 若提供 loader）或在 UNET 上套用：
  `miniH3 LoraLoader / UNETLoader + LoRA`，`strength` 对话风格权重 0.4–0.9。

### 3.3 嵌入现有 workflow

- 打开画布工作流 `workflows\v1\h3_xinniang_v1_workflow.json`；

- 在 `UNETLoader → MiniMaxH3SigmaShift` 之间插入 LoRA 节点；

- prompt 中加入触发词（如 `cn bride char`）；

- 保存为 `h3_xinniang_v2_loraload`。

- 脚本侧：在 `h3_xinniang_v1.py` 的 `build_segment` 中插入 LoRA 节点亦可，改一行即可共享。

## 4. 训练时间评估

粗估（4060 Ti）：

| 场景                          | 数据量     | 预估时间    |
| --------------------------- | ------- | ------- |
| 快速风格小 LoRA（rank16，few-shot） | 30–50 条 | 1–3 小时  |
| 通用风格 LoRA                   | 100 条   | 4–10 小时 |
| 单一人设角色 LoRA（高质量）            | 300+ 条  | 0.5–2 天 |

> 实际受帧长、分辨率、epoch 数、是否离线缓存影响，波动大。首次可先用小数据试跑看显存与收敛。

***

## 5. 风险与备选路线（重要）

**风险**：H3 本地 LoRA 训练工具不成熟 → 可能没有现成 `safetensors` 训练入口。

**备选路线（如果 H3 训练不可用，推荐）**：

- 方案 A（**几乎零成本、眼下就能用**）：不做 H3 LoRA，改用**图生视频一致性**——
  用参考图 `C02_BODY_FRONT` 作 first\_frame（现有 `h3_xinniang_v1.py` 已实现），
  人物由参考图锁定，再靠多段首尾帧保持连续。

- 方案 B：用成熟的 SDXL/Flux 训练**角色 LoRA**，用它在线下/ComfyUI 里生成**首帧参考图**，
  再把这些首帧喂给 `MiniMaxH3ImageToVideo` → 既得到想要的"人设"，又绕开 H3 训练门槛。

- 方案 C：关注 MiniMax/社区后续推出 H3 官方训练接口后，再用本文 3.1 的链路。
