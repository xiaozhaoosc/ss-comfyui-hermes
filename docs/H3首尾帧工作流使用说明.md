# H3 首尾帧（fl2v）多段视频工作流使用说明

> 适用：参考人物图 + 提示词 → Qwen-Image-2.1 生成链式关键帧 → H3 4 步 turbo 以「首帧 + 尾帧」约束生成多段 ≈3s 视频 → 硬切合并成片（保留 H3 原生音频）。
>
> 提供两条使用路径：**API 版**（AI Agent / 命令行自动执行）与 **UI 版**（人工在 ComfyUI 界面手动执行）。

---

## 0. 链路总览

```
参考人物图 + 提示词/分镜
        │
        ▼  ① 关键帧（Qwen-Image-2.1 保身份编辑）
   K0 ── K1 ── K2 ... ── KN        （N 段 → N+1 张关键帧，链式衔接）
        │
        ▼  ② 分段视频（H3 4 步 turbo，首尾帧双锚定，736×1088）
   s1 = K0→K1    s2 = K1→K2   ...  （每段 73 帧 ≈ 3.04s，含原生音频）
        │
        ▼  ③ 合并（硬切 concat + 音频同步）
   final_merged.mp4
```

链式规则：第 i 段用 **K(i-1) 作首帧、K(i) 作尾帧**，因此段间天然衔接、全片人物一致。

## 1. 前置条件（两条路径通用）

1. **ComfyUI 单实例运行**：`http://127.0.0.1:8188`（多实例会抢显存/端口）。
2. **依赖齐全**：`comfy-kitchen ≥ 0.2.33` + `triton-windows`；SLA 相关节点（`H3SLAAttention`、`MiniMaxChunkFeedForward`、`MiniMaxH3SigmaShift`）在 `/object_info` 可查。
3. **模型文件在位**：

   | 用途 | 文件名 | 目录 |
   |---|---|---|
   | H3 视频主模型（4 步 turbo 融合） | `minimax_h3_fused_refdelta_r1024_turbo8_mystic07_int8_convrot.safetensors` | `models/diffusion_models/` |
   | H3 文本编码器 | `qwen3vl_32b_heretic_minimax_h3_nvfp4.safetensors` | `models/text_encoders/` |
   | H3 视频 VAE（**必须 fp16**） | `minimax_h3_video_vae_fp16.safetensors` | `models/vae/` |
   | H3 音频 VAE | `minimax_h3_audio_vae_fp32.safetensors` | `models/vae/` |
   | 关键帧扩散模型 | `qwen-image-2.1-UC-Q4_K_M.gguf` | `models/unet/` |
   | 关键帧文本编码器（**编辑需视觉塔，不能用 GGUF**） | `qwen3vl_8b_int8_convrot.safetensors` | `models/text_encoders/` |
   | 关键帧 VAE | `qwen_image_2.1_vae_bf16.safetensors` | `models/vae/` |

4. **视觉塔补丁在位**（关键帧编辑必需）：`comfy/sd.py` 的 `CLIPType.QWEN_IMAGE + TEModel.QWEN3VL_8B` 分支内需有 `model.visual. → visual.` 的 `state_dict_prefix_replace`。ComfyUI 升级覆盖后需重新打补丁；API 脚本会预检并在缺失时直接报错。
5. **输入输出约定**：输入图放 `input/`；产出统一落 `output/<YYYY-MM-DD>/<项目名>/`。
6. **命令行一律使用项目 venv**：`D:\ai_projects\ComfyUI\venv\Scripts\python.exe`。

## 2. API 版使用步骤（AI Agent / 命令行）

工作目录：`D:\ai_projects\ComfyUI`。

### 2.0 准备素材

- 把**参考人物图**放进 `input/`（建议竖构图，见 §4 说明）。
- 写一份**分镜脚本** `story.json`（契约见 2.3）。

### 2.1 （可选）生成单张关键帧 —— 调试用

```powershell
& "D:\ai_projects\ComfyUI\venv\Scripts\python.exe" "tools\qwen_keyframe_submit.py" `
  --ref-image "参考人物.jpg" `
  --prompt "a medium portrait of the same person standing indoors, soft window light, neutral calm expression" `
  --seed 42 --output-prefix "2026-10-02/my_project/kf/test"
```

- `--dry-run`：只做逐节点校验，不提交。
- 输出：`output/2026-10-02/my_project/kf/test_00001_.png`，并打印亮度（>3 视为非黑屏）。
- 预检会硬校验「视觉塔补丁在位 + CLIP 非 GGUF 且 type=qwen_image」。

### 2.2 （可选）生成单段首尾帧视频 —— 调试用

```powershell
& "D:\ai_projects\ComfyUI\venv\Scripts\python.exe" "tools\h3_fast_submit.py" `
  --prompt-file "motion.txt" `
  --first-frame "首帧.png" --last-frame "尾帧.png" `
  --width 736 --height 1088 --length 73 `
  --seed 20261002 --prefix "2026-10-02/my_project/seg"
```

- 传 `--last-frame` 时会**自动选用 FL2V 工作流** `workflows/v5/h3_fast_fl2v_9x16_api.json`；不传则等同首帧（兼容原 i2v 用法）。
- `motion.txt` 写「从首帧到尾帧的运动描述」，可含 `overall_soundscape` / `non_diegetic_music`。
- 加 `--no-wait` 只提交不等待；不加则等待并自动抽帧验收（黑屏会判失败）。

### 2.3 推荐：一键端到端流水线

**分镜契约 `story.json`**

```json
{
  "project": "my_project",
  "final_keyframe_desc": "英文：全片最后一帧的构图/动作/表情/场景描述",
  "segments": [
    {
      "keyframe_desc": "英文：本段起始关键帧的构图/动作/表情/场景描述",
      "motion_prompt": "英文：从本段首帧到尾帧的运动描述；overall_soundscape: 环境音；non_diegetic_music: 配乐"
    }
  ]
}
```

> N = `segments` 长度。生成关键帧 **K(0)…K(N)**：`K(i)=segments[i].keyframe_desc`（i=0..N-1），`K(N)=final_keyframe_desc`。

**执行**

```powershell
& "D:\ai_projects\ComfyUI\venv\Scripts\python.exe" "tools\h3_fl2v_pipeline.py" `
  --ref-image "参考人物.jpg" `
  --story "output\2026-10-02\my_project\story.json" `
  --segments 3 --seg-len 73 --width 736 --height 1088 `
  --seed 20261002 `
  --prefix "2026-10-02/my_project/fl2v"
```

**主要参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--ref-image` | 内置示例 | `input/` 下的参考人物图相对路径 |
| `--story` | 必填 | 分镜脚本 JSON |
| `--segments` | `segments` 长度 | 覆盖段数 N（不得大于 story 提供的段数） |
| `--seg-len` | `73` | 每段帧数，自动对齐到 17k+5 网格（73≈3.04s） |
| `--width` / `--height` | `736` / `1088` | 竖屏 9:16；建议 32 的倍数 |
| `--seed` | `20261002` | 关键帧用 `seed+j`，第 i 段用 `seed+i` |
| `--prefix` | `<日期>/<project>/fl2v` | 输出前缀（相对 `output/`） |
| `--transition` | `cut` | `cut`=硬切无叠影（推荐）；`crossfade`=交叉溶解（有鬼影风险） |
| `--xfade` | `0.3` | crossfade 时长（秒） |
| `--dry-run` | 关 | 只预检 + 逐节点校验两个工作流，不提交 |
| `--no-wait` | 关 | 只提交不等待 |
| `--skip-keyframes` | 关 | 跳过关键帧生成，复用 `input/fl2v_<project>_k*.png` |
| `--merge-only` | 关 | 跳过生成，仅拼接已存在的分段 |
| `--keyframe-workflow` / `--fl2v-workflow` | 内置 | 覆盖工作流路径 |

**产物**

```
output/2026-10-02/my_project/
├── fl2v/kf/k0_00001_.png ... k3_00001_.png   关键帧
├── fl2v/s1_00001_.mp4 ... s3_00001_.mp4      分段视频（含音频）
└── fl2v_merged.mp4                           最终成片（硬切 + 原生音频）
input/fl2v_my_project_k0.png ... k3.png       供 LoadImage 复用的稳定命名副本
```

### 2.4 复用与重拼

```powershell
# 关键帧已生成，只跑分段+合并
... --skip-keyframes --ref-image "参考人物.jpg" --story "story.json"

# 分段已存在，仅重新拼接（改 --transition / --xfade 时免重跑）
... --merge-only --story "story.json" --prefix "2026-10-02/my_project/fl2v"
```

### 2.5 干跑（不消耗 GPU）

```powershell
... --dry-run --ref-image "参考人物.jpg" --story "story.json"
```

## 3. UI 版使用步骤（人工在 ComfyUI 手动执行）

UI 工作流文件：

- 首尾帧视频：`workflows/工作流/低显存版工作流/06_fl2v_4step_sla_lowvram_fast.json`
- 关键帧生成：`workflows/工作流/低显存版工作流/07_qwen_keyframe_2_1_edit.json`

> 文件内已内嵌 **Note 节点**，写明手动步骤，导入后可直接照做。

### 3.1 导入

1. 打开 ComfyUI 界面 → 把上述 `.json` 拖入画布（或 `Workflow → Open`）。
2. 确认无红框/缺失节点（本机已验证节点齐全）。
3. 参考人物图先放入 `input/` 目录，才能在下拉里选中。

### 3.2 第一步：生成关键帧（用 `07_qwen_keyframe_2_1_edit.json`）

1. `LoadImage` 选择**参考人物图**。
2. 改 `TextEncodeQwenImageEditPlus` 的正面提示词为**该关键帧的构图/动作/表情/场景**描述（负向可保留默认）。
3. 需要几张关键帧就改几次提示词、点几次 **Queue**（每张换一个 seed 便于复现）。
4. 结果保存到 `output/2026-10-02/keyframe/kf`。
5. 把生成的关键帧**复制到 `input/`**（或记住输出路径），供下一步 `LoadImage` 选择。

> 关键帧比例**跟随参考图**：要 9:16 关键帧，参考图就用竖构图。

### 3.3 第二步：生成分段视频（用 `06_fl2v_4step_sla_lowvram_fast.json`）

1. 两个 `LoadImage`：**FIRST FRAME（首帧）** 选 K(i-1)，**LAST FRAME（尾帧）** 选 K(i)。
2. 填提示词（`PrimitiveStringMultiline`）：描述**从首帧到尾帧的运动**，含 `overall_soundscape` / `non_diegetic_music`。
3. 设定：分辨率 **736×1088**（H3 节点宽高控件），帧长 **73**（≈3.04s，落在 17k+5 网格）。
4. 点 **Queue** 执行，产出 `.mp4`（含 H3 原生音频）。
5. 接着做下一段：把上一段的**尾帧**改成本段首帧、下一张关键帧作尾帧，重复即可。

### 3.4 第三步：合并成片

N 段全部生成后，两种方式任选：

**方式 A：命令行拼接（推荐，硬切 + 音频同步）**

```powershell
# 以 2 段为例；多段自行追加 -i 并调整 concat=n=
ffmpeg -y -i s1_00001_.mp4 -i s2_00001_.mp4 `
  -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1[v][a]" `
  -map "[v]" -map "[a]" -c:v libx264 -preset medium -crf 20 -r 24 `
  -c:a aac -b:a 192k -movflags +faststart merged.mp4
```

**方式 B：复用流水线的拼接器（自动探测时长/音轨，免手工写 filter）**

```powershell
# 需分段文件名形如 s1_*.mp4 / s2_*.mp4，且位于 output/<prefix>/
& "D:\ai_projects\ComfyUI\venv\Scripts\python.exe" "tools\h3_fl2v_pipeline.py" `
  --merge-only --story "output\2026-10-02\my_project\story.json" `
  --prefix "2026-10-02/my_project/fl2v"
```

## 4. 规格与参数速查

| 项目 | 值 |
|---|---|
| 画幅/分辨率 | 736×1088 竖屏 9:16（建议 32 的倍数） |
| 每段帧数（时长） | 73 帧 ≈ 3.04s（H3 网格 17k+5：56 / 73 / 90 / 107 / 124 / 175…） |
| 帧率 | 24 fps |
| 采样 | 4 步 turbo（单步成本与 28 步基线同量级），快线单段执行 ≈2.7 min（736×1088×73，模型驻留后） |
| 音频 | SaveVideo 自带 H3 原生音频（AAC） |
| 关键帧比例 | 跟随参考图；参考图为竖构图才得 9:16 关键帧 |
| 输出归档 | `output/<YYYY-MM-DD>/<项目名>/` |

## 5. 常见问题 / 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 视频全黑、但有音频 | 用了 int8 视频 VAE | 视频 VAE 必须换成 `minimax_h3_video_vae_fp16.safetensors` |
| 关键帧生成报错 / 人物不像 | 视觉塔补丁缺失，或用了 GGUF 文本编码器 | 确认 `comfy/sd.py` 的 QWEN_IMAGE 分支补丁在位；CLIP 用 `qwen3vl_8b_int8_convrot.safetensors`（type=qwen_image） |
| 末帧没有贴合尾帧 | **抽帧方法误判** | 判尾帧必须用精确帧索引：`ffmpeg -i x.mp4 -vf "select=eq(n\,72)" -vsync 0 -frames:v 1 out.png`，或用 `-sseof -0.05`；`-ss <t>` 会取到非末帧 |
| 预览像卡住/很慢 | 显存或内存不足、队列争用 | 确保单实例、空闲内存充足；批量生产建议串行独占 GPU |
| 拼接处有双重曝光叠影 | 用了交叉溶解（crossfade）且两段画面未严格对齐 | 改用硬切 `--transition cut`（默认） |
| 提交后 node_errors 非空 | 工作流参数/节点不匹配 | 先跑 `--dry-run` 定位到具体节点 |
